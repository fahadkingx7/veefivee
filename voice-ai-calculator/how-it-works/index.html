The big picture

There are two different connections. Retell handles the live voice conversation; our Cloudflare Worker handles the text messages between Retell and the language model. The Worker does not transmit raw phone audio or replace a phone carrier.

In one sentence: Caller speaks → Retell transcribes → Worker sends text to DeepInfra → Qwen writes an answer → Worker returns text → Retell speaks it. Repeat until the call ends.

Who does what?

Keep the services separate in your mind. Each has one job.

Retell AI — the ears and voice

Accepts inbound or outbound calls, converts speech into text, manages turn-taking and interruption behavior, and turns the AI reply into spoken audio. It also handles the custom-LLM integration with your WebSocket endpoint.

Cloudflare Worker — the messenger

A small serverless program that accepts Retell's WebSocket messages, validates them, constructs the LLM request, calls DeepInfra over HTTPS, and sends the reply back in Retell's expected format.

DeepInfra — the brain

Hosts Qwen3.5 9B, so you do not buy a GPU or manage a model server. It receives text context and returns the next response. Verify the model's current availability, exact model ID, pricing and API support before building.

Phone provider — the connection

A phone number and carrier route may be supplied through Retell or a connected provider. This is included in the calculator's combined planning rate, not an extra fee by default. Confirm actual billing to avoid double-counting.

The full build plan

Follow these stages in order. Build a simple working conversation first; only then add advanced sales behavior, CRM actions and analytics.

01

Create the Retell agent

Create a Retell account and a voice agent. Choose the custom LLM / bring-your-own-LLM integration, select voice and language, and configure a phone number or test call. Locate the setting for the custom WebSocket URL. Keep the agent's voice/turn-taking in Retell, not in the Worker.

02

Create the DeepInfra API key

Open DeepInfra, enable billing if required, choose the intended Qwen3.5 9B model, and copy its exact model identifier and OpenAI-compatible chat-completions endpoint from DeepInfra documentation. Test a single HTTPS completion first. Store the key privately — never in the website's JavaScript or public GitHub repository.

03

Create a separate Cloudflare Worker project

Make a new Worker for the bridge (for example, voice-llm-bridge). Do not mix the private Worker with the public cost calculator page. Add environment secrets for DEEPINFRA_API_KEY and a Retell connection-authentication secret if supported by your chosen handshake.

04

Implement the WebSocket endpoint

Expose an HTTPS endpoint such as https://voice-llm-bridge.<account>.workers.dev/retell that accepts a WebSocket upgrade. Parse Retell's actual custom-LLM message schema and send responses using the corresponding schema. Implement the handshake, call-start, turn messages, streaming/final responses, call-end and error handling exactly as documented for the version in use.

05

Translate Retell messages into DeepInfra requests

Build a compact system prompt for your business, send the latest conversation turns to DeepInfra's chat API, and return only the text the caller should hear. Avoid sending raw audio to DeepInfra. Support incremental replies if Retell's integration and the selected DeepInfra model permit streaming; otherwise test non-streaming latency first.

06

Connect Retell to the Worker

Paste the deployed wss:// Worker URL into the Retell custom-LLM configuration. Make a test call. Confirm that the Worker receives the turn, DeepInfra returns a response, and Retell speaks it. Test the exact authentication and WebSocket handshake with Retell, not just a browser WebSocket test.

07

Add real business behavior

Write a short, structured sales/receptionist prompt: business identity, greeting, qualifying questions, polite objection handling, appointment offer, boundaries and when to transfer to a human. If appointments or CRM writes are needed, add authenticated server-side tools later — never let the model invent a successful booking.

08

Test, monitor and launch

Measure first-response latency, interruptions, dropped WebSockets, API errors, total call cost and user satisfaction. Start with a few controlled calls before enabling real customers or outbound campaigns. Confirm recording consent and calling rules for the countries involved.

What happens during one call?

Think of the Worker as a translator between two APIs. This is conceptual pseudocode, not a drop-in Retell integration: the exact message names and payload fields must come from the current Retell documentation.

RETELL (WebSocket)                 CLOUDFLARE WORKER                 DEEPINFRA (HTTPS)
     |                                   |                                  |
     |  Call begins / metadata          |                                  |
     |---------------------------------->|                                  |
     |  Transcript + current turn       |                                  |
     |---------------------------------->|  Chat completion + context       |
     |                                   |--------------------------------->|
     |                                   |      Generated response          |
     |  Retell-compatible reply         |<---------------------------------|
     |<----------------------------------|                                  |
     |  Retell converts text to speech  |                                  |
     |  Caller responds; repeat         |                                  |
     |  Call ends                       |                                  |
     |---------------------------------->|  Clean up state                  |

System prompt

Instructions for how the AI should behave. Example: “You are a helpful, concise phone receptionist. Ask one question at a time. Never invent prices or bookings.”

Conversation context

The most recent caller and agent messages. Keep it short to reduce cost and delay, but preserve critical facts like name, intent and appointment preference.

Streaming and interruption

Retell may need partial text responses and interruption handling. Implement exactly the expected protocol. Do not assume a generic WebSocket chat message is enough.

Failure behavior

Timeout or upstream error? Return a safe short fallback, optionally offer a transfer, and close or recover the call cleanly. Never expose API errors to the caller.

Security and reliability

Protect secrets

  • Keep DeepInfra keys in Cloudflare Worker secrets.
  • Authenticate the Retell WebSocket connection using supported credentials or signature mechanisms.
  • Use HTTPS/WSS only and reject unexpected requests.
  • Never place private keys in the calculator or repository.

Keep calls responsive

  • Limit prompt size and response length.
  • Use timeouts and cancellation for interrupted turns.
  • Measure p50 and p95 end-to-end response latency.
  • Handle retries carefully to avoid duplicate spoken replies.

Control spend

  • Set DeepInfra budget and usage alerts if available.
  • Rate-limit new sessions and cap per-call turns.
  • Track tokens per call and real Retell minutes.
  • Review Cloudflare Worker usage before scaling.

Respect privacy

  • Minimize personal data in prompts and logs.
  • Use retention limits for transcripts and recordings.
  • Get consent where recording/AI disclosure is required.
  • Review telemarketing, DNC and outbound calling rules.

Important engineering check: A basic Worker can accept WebSockets, but live session duration, CPU/subrequest limits, connection handling and billing depend on Cloudflare's current plan and runtime limits. Validate these with a sustained real call before assuming the free tier covers production usage. For stateful sessions or recovery, consider Durable Objects only if testing shows a need.

Test plan and launch criteria

Phase 1 · Proof of concept

Connect one Retell test agent to one Worker and one DeepInfra model. Verify greeting, a multi-turn conversation, a goodbye and call termination. No CRM required.

Phase 2 · Reliability

Test 1, 5 and 15-minute calls; silence, interruptions, slow upstream responses, invalid credentials, caller hang-ups and simultaneous calls. Record latency and errors.

Phase 3 · Business logic

Add company knowledge, qualification, objections, human handoff and optional appointment tools. Review transcripts for factual accuracy and consent compliance.

Phase 4 · Small rollout

Run a limited number of real calls, reconcile actual Retell/DeepInfra bills with estimates, tune prompts and increase volume gradually.

Questions your developer will ask

Do we need a VPS or GPU?

No for this design. DeepInfra hosts the model; Cloudflare hosts the bridge. Confirm Cloudflare limits for your actual traffic.

Does Cloudflare replace Retell?

No. Retell handles calls, speech, voices and turn-taking. Cloudflare only connects Retell to DeepInfra and runs your integration logic.

Why use a WebSocket?

Retell's custom-LLM integration uses a live two-way connection to exchange events and replies during the call. DeepInfra can be called separately over HTTPS from the Worker.

Can the AI schedule appointments?

Yes, once you add a secure calendar or CRM integration. The model must call an authenticated tool and wait for confirmation before claiming the appointment is booked.

What if the voice agent feels slow?

Measure transcription-to-first-audio delay. Reduce prompt/history, limit response length, stream where supported and test model/provider latency. Cloudflare alone cannot fix a slow model or speech engine.

Is the system already live?

No. This page is the implementation masterplan. The calculator is a static planning tool. The private Cloudflare Worker, DeepInfra integration and Retell connection still need to be built and tested.
